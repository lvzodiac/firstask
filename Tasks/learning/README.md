# 用你的 GM6020 工程学 CAN 和 PID

这份讲义以当前 `Tasks` 源码为准。它是学习资料，不会更改控制程序或 PID 参数，也没有上传 GitHub。原控制协议仍是 `0x1FE/0x2FE` 电流给定。

目标不是背出注释，而是面对一行代码，能说明：输入是什么、输出是什么、单位是什么、为什么这样写、少了这一行会怎样。

## 2. 先看完整过程

速度模式的主线：

```text
正弦目标转速 ref（rpm）
          |
          v
目标转速 - 实际转速 = 误差（rpm）
          |
          v
速度 PI -> 电流给定码值 -> CAN 发送 -> 电机驱动器 -> 电机运动
  ^                                                    |
  |________________ CAN 反馈实际转速 ___________________|
```

CAN 负责传递数据。PID 负责根据误差计算控制量。电机驱动器负责把电流给定变成实际驱动，内部还有电流闭环。

STM32 没有通过 CAN 传递电机所需的大功率电能。电机仍需要独立供电。CAN 线上传的是数字指令和反馈。

“电流控制模式”与“速度闭环”可以同时成立：前者描述驱动器接受的指令，后者描述 STM32 想控制的物理量。

本工程的 `MainTask` 不是操作系统任务。工程没有用 RTOS，它由 TIM6 定时器中断每 1ms 调用一次。`main` 的 `while(1)` 虽然为空，中断仍在运行。

### 小练习

目标是 100rpm，反馈是 80rpm：哪个模块算出差值 20？哪个模块把算出的控制量送给电机？

答案：`Pid::calc` 算误差和控制量；`Gm6020::encode` 打包，`HAL_CAN_AddTxMessage` 提交给 CAN 外设发送。

## 3. CAN：从接线到报文

### 3.1 本工程用的是经典 CAN

CAN 是允许多个节点共享总线的通信协议。STM32 的 CAN 控制器处理报文、仲裁、校验等；收发器把控制器的逻辑信号变成 CAN_H/CAN_L 差分电平。

你这块开发板的 CAN 接口应通过板载收发器接电机。不要把 MCU 的 TX/RX 引脚直接当 CAN_H/CAN_L 接线。

基本检查：CAN_H 对 CAN_H，CAN_L 对 CAN_L，设备参考地按硬件说明正确连接；电机电源正确；总线两端各一个 120Ω 终端电阻，避免每个节点都随意加终端。断电测量正常双终端总线 H/L 间通常接近 60Ω。电机第 4 位拨码与终端电阻有关，前三位用于设置电机 ID。

### 3.2 一帧包含什么

| 内容 | 本工程的例子 | 作用 |
| --- | --- | --- |
| 标识符 ID | `0x1FE` 或 `0x206` | 区分报文含义，同时参与仲裁 |
| IDE | `CAN_ID_STD` | 标准帧，11 位 ID；扩展帧为 29 位 |
| RTR | `CAN_RTR_DATA` | 数据帧，携带实际数据 |
| DLC | `8` | 本帧数据区有 8 字节 |
| DATA | `00 00 03 E8 00 00 00 00` | 电机控制数值 |
| CRC、ACK 等 | 由外设处理 | 检错、应答等 |

8 字节是经典 CAN 的最大数据区长度，不是整帧总长度，也不是所有 CAN 技术的统一上限。CAN FD 不属于本工程范围。

ID 不是 CAN 强制规定的“收件人地址”。这是共享广播总线，节点根据 ID 和应用协议决定如何处理。标准数据帧之间同时竞争总线时，一般较小 ID 的优先级更高，因为显性位 0 能覆盖隐性位 1。

接收到 ACK 只能说明有其他节点确认了有效报文，不能证明目标电机执行了指令，更不能证明它已达到目标转速。

### 3.3 电机 ID 和报文 ID

当前 `MOTOR_ID=2` 是电机拨码配置。

```text
电机 ID = 2
反馈报文 ID = 0x204 + 2 = 0x206
控制报文 ID = 0x1FE
该电机的控制数据位置 = DATA[2]、DATA[3]
```

电流控制分组：

| 电机 ID | 控制报文 ID | 数据下标 | 反馈报文 ID |
| --- | --- | --- | --- |
| 1 | 0x1FE | 0、1 | 0x205 |
| 2 | 0x1FE | 2、3 | 0x206 |
| 3 | 0x1FE | 4、5 | 0x207 |
| 4 | 0x1FE | 6、7 | 0x208 |
| 5 | 0x2FE | 0、1 | 0x209 |
| 6 | 0x2FE | 2、3 | 0x20A |
| 7 | 0x2FE | 4、5 | 0x20B |

本地 GM6020 手册区分了电压指令 `0x1FF/0x2FF` 和电流指令 `0x1FE/0x2FE`。电流控制需要相应固件和电流环配置。沿用你已经能转动的电流协议，不因旧变量名叫 `voltage_` 就切换协议。

电流给定 `-16384..16384` 对应约 `-3..3A`，所以给定 1000 大约是 0.183A，不是 1000A，也不是 1000rpm。这是电流给定的码值范围，不是 `int16_t` 的完整存储范围。

### 3.4 波特率与发送频率

`Core/Src/can.c` 中：CAN1 外设时钟为 42MHz，预分频 3，BS1=6TQ，BS2=7TQ，再加固定同步段 1TQ。

```text
CAN 位速率 = 42MHz / [3 × (1 + 6 + 7)] = 1Mbps
一位时间 = 1us
反馈频率 = 1kHz，约每 1ms 一帧
控制频率 = 1kHz，约每 1ms 提交一帧
```

1Mbps 是每秒传输的位数；1kHz 是每秒发生的帧或控制计算次数。两者不是同一件事。一帧还包含 ID、CRC、ACK、帧间隔和可能的填充位，不能只用 64 位数据计算总线负载。

### 3.5 过滤器、FIFO、中断

过滤器决定哪些报文进入接收队列；FIFO 是先进先出的硬件缓存；中断通知 CPU 有新数据。

掩码过滤可理解为：`(收到的标识字段 & mask) == (配置字段 & mask)`。mask 某位为 1，才要求对应位相同。全零掩码相当于全部放行，不等于拒收全部。

当前代码全零掩码也没有限制 IDE/RTR，因此“只收标准帧”的注释不准确。并且 F407 的 CAN1/CAN2 共享过滤器，还需要正确配置 `SlaveStartFilterBank`，见代码现状。

初始化顺序的概念：先配置硬件，再配置过滤器，再启动 CAN，再打开接收通知。初始化失败要处理，不能仅凭调用过函数就认为已经成功。

## 4. 逐字节读懂 GM6020

### 4.1 字节和十六进制

一个字节 8 位，能表示 0 到 255。两个字节 16 位。十六进制的每一位对应 4 个二进制位，`0x` 只是十六进制写法的前缀。

```text
十进制 1000 = 十六进制 0x03E8
高字节 0x03 = 3
低字节 0xE8 = 232
3 × 256 + 232 = 1000
```

GM6020 协议规定高字节在前，也叫大端字节顺序。MCU 自身是小端，并不妨碍手工按协议编码。协议字节顺序与内存字节顺序不是同一概念。

### 4.2 接收：两个字节变一个数

```cpp
uint16_t raw = static_cast<uint16_t>((data[0] << 8) | data[1]);
```

`data[0]` 是高字节；左移 8 位相当于放到 16 位数的高半部分；`|` 是按位或，把低字节合并进来。这里高低位互不重叠，所以结果也等于高字节乘 256 加低字节。

```text
data[0]=0x03，data[1]=0xE8
0x03 << 8 = 0x0300
0x0300 | 0x00E8 = 0x03E8 = 1000
```

`|` 和 `||` 不同，`&` 和 `&&` 也不同：前者操作每一个二进制位，后者判断真假。

### 4.3 负数与补码

有符号 16 位数使用补码表示。在当前 ARM GCC 环境里，`0xFFFF` 转成 `int16_t` 是 -1，`0xFF9C` 是 -100。

```text
-100 的 16 位编码 = 65536 - 100 = 65436 = 0xFF9C
发送字节：FF 9C
按 uint16_t 解读是 65436；按 int16_t 解读是 -100。
```

所以角度用 `uint16_t`，转速和电流用 `int16_t`。角度原始值为 0..8191；转速和电流需要正负号表示方向。

`static_cast<int16_t>` 不会把两个字节自动变成 rpm；rpm 是协议约定的单位，类型转换只改变代码如何解释数值。

### 4.4 发送：一个数拆成两个字节

```cpp
data[index]     = static_cast<uint8_t>((voltage_ >> 8) & 0xFF);
data[index + 1] = static_cast<uint8_t>(voltage_ & 0xFF);
```

当前 `voltage_` 实际存电流给定，只是沿用了旧名字。右移 8 位取高字节，`& 0xFF` 保留低 8 位。当前工具链能按预期处理负数右移；更易移植的写法可先转为 `uint16_t`，这里先理解现有实现。

ID=2、给定 1000 时，`index=(2-1)*2=2`，整帧是：

```text
ID=0x1FE，DLC=8，DATA=00 00 03 E8 00 00 00 00
```

其余数据置零是在向同组其他电机发零给定，不是“对其他电机不做任何事情”。一条总线上如果其他电机也使用这组 ID，要统一打包，不能让多个发送函数互相覆盖。

`setCurrent` 只修改 RAM 里的给定值，`encode` 只写数据数组，真正提交 CAN 发送的是 `HAL_CAN_AddTxMessage`。这三个步骤要能分开解释。

### 4.5 反馈帧

| 字节 | 意义 | 解读方法 |
| --- | --- | --- |
| 0、1 | 原始机械角度 | 无符号，0..8191 |
| 2、3 | 转速 | 有符号，rpm |
| 4、5 | 实际转矩电流原始值 | 有符号码值 |
| 6 | 温度 | 单字节，℃ |
| 7 | 保留 | 当前代码不使用 |

例：`10 00 FF 9C 03 E8 28 00` 表示原始角度 4096，即单圈 180°；转速 -100rpm；电流原始值 1000；温度 40℃。`current()` 按原代码的 `3/16384` 做安培估算；手册明确给定值的这个映射，反馈值的精确标度应结合实际固件确认，不把估算当成额外测量结论。

### 4.6 跨圈角度

原始角度只表示一圈内的位置，转过零点会从 8191 跳到 0。位置环需要连续角度，否则误差会突然接近 360°。

```text
前一帧 8190，当前帧 2：差值 -8188 < -4096，整圈数加 1。
前一帧 2，当前帧 8190：差值 8188 > 4096，整圈数减 1。
累计编码值 = 整圈数 × 8192 + 当前原始角度
累计弧度 = 累计编码值 × 2π / 8192
```

`4096` 是半圈阈值。算法依赖相邻有效采样之间真实运动小于半圈。长时间断线后不知道到底转过几圈，不能保证累计角度仍然正确。

第一帧只能记录初始绝对角度，不能拿构造时的假初值 0 做跨圈判断；`feedback_valid_` 就解决这个问题。它不代表电机现在仍在线，在线性由反馈超时另行判断。

## 5. PID：先算得出，再谈调得好

### 5.1 误差与负反馈

`e=ref-fdb`：目标减实际。

目标 100rpm、实际 80rpm，误差为 +20rpm，正比例增益给出正向控制。实际超过目标时误差反向，促使速度回落。这要求指令正方向与反馈正方向一致，否则可能形成正反馈，越控越偏。

负电流不一定等于电机已经反转。电机正转时负电流也可能用于减速，实际运动取决于当前状态、负载和控制过程。

### 5.2 三项分别负责什么

| 项 | 看什么 | 本代码的计算 | 参数过大可能怎样 |
| --- | --- | --- | --- |
| P，比例 | 当前误差 | `p=kp_*err` | 反应激烈、过冲、振荡 |
| I，积分 | 过去误差的积累 | `integ_+=ki_*err` | 误差过零后仍积累较多，恢复慢或振荡 |
| D，微分 | 误差变化速度 | `d=kd_*(err-last_err_)` | 放大噪声、给定突变时冲击 |

P 对“现在差多少”做反应。I 给持续的小误差逐渐增加补偿，常用于减小恒定给定下的稳态误差。D 对误差变化做反应，在合适条件下能改善阻尼；它不是直接测量未来，也不保证一定减少抖动。

有摩擦、负载和电机惯性时，同一个电流给定不对应唯一转速。因此不能直接把目标 rpm 数值当成电流给定发送。

### 5.3 连续公式和代码公式的关系

理论中常见的形式：

```text
u(t) = Kp e(t) + Ki_cont × ∫e(t)dt + Kd_cont × de(t)/dt
```

固定采样周期 T，简化离散化后：

```text
I[k] = I[k-1] + Ki_cont × T × e[k]
D[k] = Kd_cont / T × (e[k]-e[k-1])
```

本工程把周期吸收到参数里：`ki_=Ki_cont*T`，`kd_=Kd_cont/T`。`calc` 没有再乘或除 T，不是遗漏，而是参数定义不同。改变调用周期会改变实际 I、D 的作用，不能只改 `CONTROL_PERIOD_S` 就以为保持了同一控制器。

当前参数：速度环 Kp=15、Ki=1、Kd=0，实际为 PI；位置环 Kp=8、Ki=0、Kd=0，实际为 P。类名叫 PID，并不代表三个分量都必须非零。

“位置式 PID”指直接算本次完整输出 `u[k]`；这与“位置闭环”是两个概念。位置式 PID 同样可以控制速度。增量式 PID 算的是本次输出增量，本工程没有使用它。

### 5.4 用真实参数手算三拍

速度环初始积分 0，目标 100rpm，三次反馈分别为 80、90、105rpm。用当前积分限幅 ±140、Kd=0：

| 拍次 | 误差 | P=15e | I=上一拍I+e | D | 输出 |
| --- | --- | --- | --- | --- | --- |
| 1 | 20 | 300 | 20 | 0 | 320 |
| 2 | 10 | 150 | 30 | 0 | 180 |
| 3 | -5 | -75 | 25 | 0 | -50 |

第三拍 I 仍为 +25，是因为它记着前面累积的误差。输出 -50 只是这一拍的电流给定码值，不能据此直接断定下一拍转速。

### 5.5 两种限幅

积分限幅把 `integ_` 限在 ±140，抑制误差长期累积。输出限幅把总和限制在 ±16384，符合电流指令范围。

`i_max` 限的是已经乘过 Ki 的积分输出项，不是原始误差和。`setCurrent` 又做了一次协议范围限幅，是不同层的保护。

当前只是积分独立限幅和输出限幅；没有做到“输出饱和时停止同方向积分”或积分回算，不能声称采用了这些更完整的抗饱和算法。

例如目标 100、反馈长期 0：P=1500，积分很快到 140，后续仍存在误差但不继续超过上限。这也说明 ±140 是否足够补偿实际摩擦和负载，要靠实机数据判断。

### 5.6 `reset` 为何要清历史

`reset` 将积分和上次误差清零。断线时继续保存旧积分，重连可能立刻输出与新状态不符的控制量。清零能去掉旧的控制记忆，但不能恢复断线时丢失的圈数。

如果日后启用 D，清零后的第一拍也可能产生误差突变造成的 D 冲击；当前 Kd=0 不会产生此项。

## 6. 正弦曲线和串级控制

### 6.1 速度曲线

```text
v_ref(t) = 100 × sin(2π × 0.25 × t) rpm
周期 = 1/0.25 = 4s
t=0、1、2、3、4s 时目标约为 0、100、0、-100、0rpm。
```

`sin` 的输入是弧度。`2πft` 是相位；振幅决定摆动范围，频率决定完成一次变化有多快。1kHz 控制频率与 0.25Hz 曲线频率各有含义。

当前 `g_tick` 每次加 1，再乘 0.001 得到控制时间，因此第一拍约为 t=0.001s，而不是严格为 0s。

速度正弦并不表示位置被限制在 ±180°。理想跟随 100rpm、0.25Hz 的速度正弦，第一段正转会累计约 764°后再回转；有机械限位的机构不能因为速度不大就忽略总行程。

### 6.2 位置曲线

```text
p_ref(t) = home + 180 × sin(2π × 0.25 × t) 度
```

`home` 在第一次进入位置模式且反馈有效时锁存。严格说不是程序启动那一瞬间的位置。累计角度转成度后参与位置环计算，不能直接把弧度当度用。

串级链路：

```text
目标位置（度） - 实际位置（度）
                |
                v
位置 P，Kp=8（rpm/度），输出目标转速，限幅 ±300rpm
                |
                v
目标转速（rpm） - 实际转速（rpm）
                |
                v
速度 PI，输出电流给定码值，限幅 ±16384
                |
                v
电机驱动器内部电流环 -> 电机
```

举例：目标位置比实际大 10°，位置 P 给出 80rpm；实际转速 60rpm，速度误差为 20rpm，再由速度 PI 算电流。位置环的输出单位是由控制器设计和参数单位决定的，不是 PID 自动推断出来的。

位置 P 输出转速属于反馈纠偏，不是轨迹导数前馈。这个工程没有加入前馈，不必为了考核引入新算法。

位置正弦的理论最大速度为 `180×2π×0.25=282.74度/s=47.12rpm`。这里 `1rpm=6度/s`。提高振幅或频率会提高最大速度，频率提高还会明显增加加速度要求。

速度内环通常应先调好、响应比外环快。当前两个环都在 1kHz 被计算，不代表两者实际响应速度相同。

```text
  -> TIM6_DAC_IRQHandler（Core/Src/stm32f4xx_it.c）
  -> HAL_TIM_IRQHandler
  -> HAL_TIM_PeriodElapsedCallback（Tasks 覆盖弱函数）
  -> MainTask

CAN1 FIFO0 有数据
  -> CAN1_RX0_IRQHandler
  -> HAL_CAN_IRQHandler
  -> HAL_CAN_RxFifo0MsgPendingCallback
  -> HAL_CAN_GetRxMessage
  -> CanFeedbackCallback
  -> Gm6020::decode
```

硬件处理位收发和帧校验，回调函数处理已经接收到的帧。你没有手动逐位实现 CAN 协议。

`HAL_TIM_Base_Start_IT` 的 IT 表示启用中断。TIM6 输入时钟为 84MHz，PSC=84-1、ARR=1000-1，所以更新频率为 `84MHz/84/1000=1kHz`。`-1` 是因为寄存器计数包含 0。

CAN 接收优先级 1、TIM6 优先级 2。在本工程优先级分组下，数值较小者抢占优先级更高，CAN 接收可打断 TIM6。因此共享数据不能仅凭“都是中断”就认为安全。

### 7.2 反馈超时

`g_lastFeedbackTick` 保存上次收到目标电机反馈时的控制计数。当前默认 100ms 对应 100 个 1ms 节拍。

`FeedbackIsFresh` 同时检查“至少收到过一帧”和“距上次反馈没有超过阈值”。当前条件为 `<=100`，所以差值 101 时判定失联。

失联分支清 PID、将电流给定置零、尝试发零指令并返回，本拍不再计算跟随。

注意：总线断线时，零指令可能根本送不到电机。软件置零与电机物理停止不是同一保证；实际停机还依赖驱动器通信超时保护和供电等条件。零电流也不意味着立即零转速。

无符号减法在计数器正常回绕时仍可计算短时间差，但要求真实间隔远小于计数器完整周期。它不解决长时间丢反馈、定时器不运行等其他问题。

### 7.3 独立看门狗 IWDG

IWDG 使用独立的低速时钟 LSI 倒计时。程序需要在超时前刷新计数器，俗称喂狗；否则 MCU 复位。

当前 `Core/Src/iwdg.c` 已初始化 IWDG，分频 64、重装载 400。按标称 LSI=32kHz：

```text
T_timeout ≈ (Reload+1) × Prescaler / f_LSI
          ≈ 401 × 64 / 32000 = 0.802s
```

LSI 有误差，因此这是估算，不能说精确 0.802s，更不是 2.56s。

`WATCHDOG_ENABLE=1` 控制的是 `FeedWatchdog` 是否执行刷新。设成 0 不会关闭已经启动的 IWDG，而是停止喂狗，最终反复超时复位。

现在 `MainTask` 在 TIM6 中断开头喂狗。因此：TIM6 不再运行、关中断卡死、某些故障阻止该中断继续执行时，可能触发复位；但主循环卡死而 TIM6 仍可运行时仍会喂狗，CAN 不在线时也仍会喂狗。不要说它能检测所有程序错误。

CAN 反馈超时保护与 IWDG 是两种机制：前者处理电机反馈失联，后者在软件停止及时喂狗时复位 MCU。IWDG 复位 MCU 也不是切断电机供电。

## 9. 上板实践顺序

以下是未来线下实验步骤，本次没有替你执行实机实验或修改固件。先固定电机、留足行程并准备断电方式；电流码值能到满量程不表示应从满量程试起。

### 实验 A：只确认反馈

先不让控制器主动带动电机，确认收到的 ID、DLC、角度、速度、温度；缓慢手转，观察角度在 0..8191 内变化、跨零后累计角度是否连续。检查时避免和通电主动控制对抗。

若没有反馈，先排查供电、CAN_H/L、终端电阻、ID、1Mbps、CAN1 接口、过滤器分配和中断，再排查 PID。改 PID 不能解决没收到报文。

### 实验 B：确认方向和简单速度响应

在低负载、低指令条件下确认正给定对应的反馈转速为正。使用较低的恒定目标更容易看 P 的响应；“临时恒定目标”是建议的实验改法，当前源码仍是正弦目标。

先只用 P（I、D 为 0）观察响应。逐步提高 P，记录是否响应更快、有无超调或持续振荡；出现持续振荡后适当减小。不要因为一组数能转动就宣布已经调好。

### 实验 C：加入积分

P 已能稳定响应后，再少量加入 I，观察恒定目标下的长期误差是否减小，是否产生低频摆动、反向恢复慢、积分长期顶住限幅。一次改一个参数，记录改前改后。

当前参数是已保留的起点，不是所有 GM6020、所有负载的最优参数。速度量化约 1rpm、摩擦、松动、供电和采样延迟都可能影响抖动。D 会放大差分噪声，不能一见抖动就加 D。

### 实验 D：再上正弦与位置环

先用较小振幅、较低频率看速度正弦跟随。目标与反馈需要画在同一时间轴，至少比较幅值、相位延迟、误差和输出是否饱和。电机“看起来很顺”不能单独证明跟随精度。

速度内环稳定后再看位置外环。位置环先保持 I=D=0，从较温和的 P 观察；留意角度单位、跨圈、home 和机械行程。改变频率后跟不上，也可能是带宽或电流/速度限幅，而非代码语法问题。

### 实验 E：验证保护

在受控条件下模拟失联，观察约超过 100 个节拍后软件给定是否归零，并独立确认电机驱动器的失联行为。不要把“调试器暂停”直接当成看门狗验证：调试冻结设置可能暂停看门狗。

验证 IWDG 时，应让程序在初始化 IWDG 后、未屏蔽看门狗且不再执行喂狗的条件下运行，再观察复位原因和复位周期。当前源码没有专门的测试开关来模拟这些故障。

记录表建议字段：模式、负载、目标曲线、Kp/Ki/Kd、积分限幅、输出限幅、波形、现象、下一次只改哪一个参数。

## 10. 当前代码现状：考官追问时要如实说

这些是源码检查结果和解释上的边界，本次没有顺手修固件。

1. `voltage_` 实际保存电流码值；`encode` 的头文件注释和位置模式的内环注释还写电压。以帧 ID、`setCurrent` 和打包行为为准，名称和注释待统一。
2. `ControlTaskInit` 关于“主循环卡死就不喂狗”的注释错误；喂狗在中断里。`WATCHDOG_ENABLE=0` 也是停止喂狗而非关闭 IWDG。
3. F407 的 CAN1/CAN2 共享过滤器。`CAN_FilterTypeDef filter={0}` 后没有设置 `SlaveStartFilterBank`，所以该成员为 0；按本地 HAL 实现会把分界写为 0，bank 0 不会被正常分配给 CAN1。必须核对并修正这处配置，常见做法是设分界为 14、CAN1 使用 bank 0。这是代码配置问题，不该靠调 PID 补偿。
4. 全零掩码会放行各类帧，接收回调没有校验 IDE、RTR、DLC 和角度范围，不能声称已经做了完整报文验证。
5. CAN 接收中断能抢占 TIM6。电机对象的多字段访问没有一致性快照，`g_tick` 也被多个中断访问却没有 `volatile`。现有两个 `volatile` 变量不是完整并发保护；32 位对齐单次访问与整组数据一致是两回事。
6. 开接收中断后才清反馈状态，初始化时可能抹掉刚收到的首帧标记。建议后续调整初始化顺序。
7. CAN 配置、启动、发包和定时器启动大多没有检查返回值。发送返回 HAL_OK 也只代表成功提交邮箱，不等于对端已执行。邮箱满、无 ACK、自动重发或 bus-off 需要另外处理；当前还禁用了自动 bus-off 恢复。
8. 反馈恢复后不会重置轨迹时间、home 或圈数累计。断线期间若运动了多圈，位置估计可能失准；重连瞬间目标也可能跳变。等待首帧期间时间仍前进，因此目标不保证从零相位开始。
9. 正弦时间是不断增加的 float。长时间运行后浮点时间分辨率降低，计数器也最终回绕；短时间考核影响有限，但不该说可以无限精度运行。
10. 上次提到的可选速度滤波尚未加入当前源码；目前没有滤波、轨迹前馈、自动整定或额外操作系统任务。不要把计划当成已经实现的功能。

## 11. 模拟考核题

先遮住答案，口头解释。答到“代码做了什么”之后，再补一句“为什么”。

| 问题 | 答案要点 |
| --- | --- |
| 你控制的是电压、电流还是速度？ | STM32 用速度/位置闭环算电流给定，经 CAN 发送；驱动器接受电流模式指令 |
| `MOTOR_ID=2` 时收发 ID 各多少？ | 反馈 0x206，电流控制 0x1FE，控制数据在 2、3 字节 |
| 为什么发 8 字节，只有两字节有效？ | 协议一帧最多容纳四个电机的给定，每个两字节；其余清零 |
| 电流给定 -100 怎么发？ | int16 补码 0xFF9C，高字节 FF，低字节 9C |
| `data[2]<<8` 为什么移 8？ | 一个字节 8 位，把高字节放到 16 位数的高位 |
| 为什么转速是 int16，角度是 uint16？ | 转速有方向符号，角度编码原值非负 |
| CAN 和 PID 谁控制误差？ | PID 根据反馈算误差和输出，CAN 传递输出和反馈 |
| 1Mbps 和 1kHz 有什么区别？ | 前者位速率，后者帧或控制计算频率 |
| `calc` 为什么没有乘 0.001？ | 本实现将周期吸收到 Ki/Kd；和未吸收周期的教材参数不同 |
| 这里真的是三个 PID 分量都开了吗？ | 速度是 PI，位置是 P，因为对应 I/D 增益为零 |
| P、I、D 过大分别怎样？ | P 可能振荡，I 可能积累过多且恢复慢，D 可能放大噪声 |
| 为什么位置环输出转速？ | 串级设计选择了这个中间物理量，参数和限幅按 rpm 设计 |
| 为何第一帧不能判跨圈？ | 没有真实的上一帧角度，不能把构造初值当反馈 |
| 为什么判断半圈而不是一整圈？ | 编码回绕表现为大于半圈的表面跳变，依赖相邻真实运动小于半圈 |
| `FeedWatchdog` 会检测主循环卡死吗？ | 当前不能保证，因为定时器中断继续运行时仍会喂狗 |
| 关闭 WATCHDOG_ENABLE 会怎样？ | IWDG 已开启，停止刷新后约 0.8s 量级复位 |
| 断 CAN 发零就保证停机吗？ | 不能；总线可能送不到，且零电流不等于瞬间零速度 |
| `volatile` 能解决所有并发问题吗？ | 不能；没有自动提供多字段快照、互斥或通用内存同步 |
| 为什么 `while(1)` 空着电机也转？ | 控制和收包在中断路径里执行 |
| 任意一行不知道怎么解释怎么办？ | 先识别语法，再追输入来源、单位、状态改变和下游用途，不能编造功能 |
